## 0. En une phrase

La V7 est un **moteur d'allocation multi-stratégies déterministe**, tournant en boucle 30 s sur
12 symboles Hyperliquid (levier 3×), où **une seule stratégie est active par régime** (exclusivité
par actif), encadré par **4 niveaux de risque** et **piloté en risque par 2 étages LLM** (un tactique
local rapide + un stratège Opus lent). Les LLM ne génèrent **pas** de signaux d'entrée : ils ne font
qu'ajuster le **seuil de stop d'urgence** et la **taille** dans des bornes dures codées en dur.

État live au cycle ~3145 : **equity 591,67 $**, régime global `range` (conf 0,60), 4 positions HL
(ETH, DOGE, SUI, ZEC), MR seule pondérée, posture stratège `defensive`, 0 coupure récente.

## 1. Analyse fonctionnelle — ce que fait le bot

### 1.1 La boucle principale (`_tick`, toutes les 30 s)

```
prix (get_all_mids) ──► candles 1h ×12 symboles ──► MarketSnapshot
   │
   ├─ detect()            → régime GLOBAL agrégé   (range/trend_up/trend_down/high_vol)
   ├─ detect_per_symbol() → régime PAR INSTRUMENT  (BTC high_vol pendant que ETH range)
   │
   ├─ _drive_grid()       → active/désactive les grilles selon le régime DU symbole
   ├─ sync_positions()    → purge les croyances stratégie si une position a été fermée hors-stratégie
   │
   ├─ generate_signals()  → MR + momentum + supertrend (la grille est event-driven, à part)
   ├─ cooldown post-emergency → bloque les RÉ-ENTRÉES d'un symbole fraîchement coupé
   ├─ [AO 5m]             → court-circuité (OFF par défaut)
   │
   ├─ allocate()          → TargetPortfolio (poids × notional × confidence × direction)
   ├─ risk.project()      → caps gross/par-actif + kill-switch / daily-loss
   ├─ emergency.check()   → force-close des positions HL dont le ROE dépasse le seuil
   ├─ reconcile()+submit()→ ordres → fills
   ├─ distribute fills    → portfolio + on_fill(stratégie) + scorer
   ├─ stop_manager        → SL natifs HL des positions MR (flag OFF par défaut)
   └─ persist             → memory/v7_state.json (consommé par le dashboard 8082)
```

### 1.2 Les stratégies (4 + 1 OFF)

| Stratégie | Rôle | Régime où elle est active | Statut |
|---|---|---|---|
| **mean_reversion** | z-score retour à la moyenne (1h, window 50, entry z=1.5) | `range` | ON — **seule pondérée actuellement** |
| **grid_engine** | grille de limits + TP, FSM event-driven, thread dédié 3 s | `high_vol` + `range` (fond) | ON, **hors allocateur** (budget propre) |
| **supertrend** | suiveur de tendance flip-only, sizing dynamique au risque | `trend_up` / `trend_down` | ON |
| **momentum** | z-score de momentum (lookback 48) | aucun régime ne lui donne du poids | ON mais **poids 0 partout** (dormant) |
| **awesome_oscillator** | AO BTC 5m, TP+SL | hors allocateur (réserverait BTC) | **OFF** — pas d'edge backtesté |

**Principe d'exclusivité (2026-06-02) :** la matrice `base_weights[régime][stratégie]` donne un poids
**non-nul à une seule stratégie par régime**. C'est le correctif structurel du bug `szi=0/frozen` : deux
stratégies sur le même compte netté se neutralisaient. La grille est sortie de l'allocateur pour ne pas
diluer la taille des entrées MR ; en `range` elle moissonne en fond mais **MR la préempte** (flat + cancel)
dès qu'elle a un setup sur un symbole.

### 1.3 Les 4 niveaux de risque (du plus fin au plus brutal)

1. **Caps par projection** (`RiskManager.project`) — gross ≤ 2× equity, par-actif ≤ 40 % equity, scaling proportionnel.
2. **EmergencyExit par position** — force-close si ROE < seuil (`emergency_exit_roe_pct`, piloté LLM ∈ [3 %, 6 %]).
   Gère aussi les orphelines (grâce + force-close) et est exempté sur le levier élevé (`high_lev_emergency_exempt`).
3. **Cooldown post-emergency** — un symbole coupé est interdit de ré-entrée pendant `emergency_cooldown_sec`
   (casse le whipsaw entrée→coupe→flip→re-coupe en marché plat).
4. **Kill-switch catastrophe** — DD ≥ 10 % **ou** perte jour ≥ 3 % → portefeuille **vide**. Hors de portée des LLM.

### 1.4 Le pilotage LLM à deux étages (gouverneur de risque)

Architecture « mur / boîte / curseur » :

- **Code = le mur extérieur** : bornes dures `emergency ∈ [3 %, 6 %]`, `size_mult ∈ [0.5, 1.2]`. Inviolables.
- **Stratège Opus = la boîte** (cadence 1 h, ~5 s/appel, budget 0,5 $) : pose une **enveloppe** (posture
  defensive/neutral/aggressive + plancher/plafond emergency + plafond taille) à partir d'un contexte large
  (trajectoire equity, régime, fréquence des coupures) + feeds **news RSS** et **on-chain whales**. Peut
  **resserrer**, jamais desserrer au-delà du mur. Apprend de son palmarès (journal noté ex-post).
- **Tactique qwen local = le curseur** (cadence 15 min) : choisit emergency + taille **dans** l'enveloppe.

L'apprentissage est **expérientiel** : chaque décision est journalisée puis **notée ex-post** sur une fenêtre
(réalisé positif sans coupure = BON ; toute coupure en perte = MAUVAIS), et le palmarès est réinjecté dans
le prompt. Persistant cross-restart (`memory/governor_journal.jsonl`, `strategist_journal.jsonl`).

> ⚠️ Les LLM **ne décident d'aucune entrée**. Tout signal directionnel est **déterministe**. C'est voulu :
> les LLM ne touchent qu'aux freins, jamais à l'accélérateur.

## 2. Analyse organique — comment c'est construit

### 2.1 Modules (par responsabilité)

| Couche | Module | Responsabilité |
|---|---|---|
| **Composition** | `main.py` (V7Bot) | Composition root + boucle + 4 threads |
| **Lecture marché** | `execution/hyperliquid_adapter.py` | Read-only HL : mids, candles, positions, equity, funding |
| **Régime** | `regime/detector.py` + `features.py` | Labels global + par-symbole ; ADX, hurst, autocorr, vol percentile, supertrend |
| **Stratégies** | `strategies/*.py` | MR, momentum, supertrend, grille (FSM), AO |
| **Allocation** | `allocation/allocator.py` + `performance.py` | Matrice régime→poids × score perf borné → TargetPortfolio |
| **Risque** | `risk/manager.py`, `emergency_exit.py`, `stop_manager.py` | Caps, kill-switch, force-close, SL natifs |
| **Exécution** | `execution/engine.py`, `paper.py`, `hyperliquid_write_adapter.py`, `boot_reconciler.py`, `order_registry.py`, `bandit_policy.py` | Reconcile/submit, paper vs live, boot, OID tracking, bandit maker/taker |
| **Gouverneur** | `governor/risk_governor.py`, `strategist.py`, `journal.py` | 2 étages LLM + apprentissage |
| **Feeds** | `feeds/news_feed.py`, `onchain_feed.py` | RSS + Whale Alert (contexte stratège, temps réel non historisé) |
| **Config** | `core/config.py` + `config/allocation.yaml` | Config typée validée |
| **Backtest** | `backtest/*` | Moteur + **harnais walk-forward OOS** (cf. §4) |

### 2.2 Concurrence : 4 threads

| Thread | Cadence | Rôle |
|---|---|---|
| principal (`run`) | 30 s | le `_tick` analytique complet |
| `grid-loop` | 3 s | FSM grille (fills, TP, drift, dégel) — découplé du tick lent pour réagir vite (sinon buy+sell se remplissent entre 2 ticks → `szi=0`) |
| `governor` | 15 min | tactique qwen |
| `strategist` | 1 h | stratège Opus |
| `watchdog` | 30 s | re-exec le process si le tick ne progresse plus depuis 180 s (anti-hang) |

Verrou partagé `_grid_lock` (RLock) entre thread principal (activation) et thread grille (FSM).

### 2.3 Flux de données et persistance

- **Source de vérité positions en live** = HL (`get_positions_detailed`), **pas** le portfolio interne (les
  fills internes de la grille ne passent pas par l'ExecutionEngine).
- `BootReconciler` au démarrage live : hydrate positions + equity + registry, **adopte** les positions MR.
- État écrit chaque tick dans `memory/v7_state.json` → lu par le dashboard (port 8082).
- Services systemd user : `sdm-main` (→ V7), `sdm-dashboard-v7` (8082), `sdm-orderflow-hf`, `sdm-exec-bandit`.

### 2.4 Points de fragilité connus (cicatrices, toutes traitées)

- **`szi=0`/frozen** : résolu par exclusivité + grille hors allocateur + thread grille rapide.
- **Crash-loop boot** : retry/backoff borné dans `main()` (storm réseau 06-12).
- **Runaway emergency** : cause racine = échec init wallet réseau → mode public 12 h ; fix = check connectivité + reconnexion paresseuse.
- **Orphelines après restart** : BootReconciler adopte désormais les positions MR au boot.
- **Whipsaw en chop** : cooldown post-emergency + régime par instrument.
- **SL MR `stop_price` no-op** : résolu via NativeStopManager (flag OFF par défaut).

## 4. Options de recherche

### 4.1 Ce qui a été fait aujourd'hui (sprint quant via le harnais OOS)

Le harnais `backtest/evaluator.py` (split train/test walk-forward, frais réalistes, **gate sévère** :
≥30 trades OOS, ≥80 % folds positifs, PF médian ≥1,05, t-stat ≥1,5) a jugé chaque hypothèse. **Tout rejeté :**

| Hypothèse | Verdict |
|---|---|
| Funding fade extrême (par symbole) | REJET — carry réel mais noyé par le risque de queue |
| Funding harvest market-neutral + carry | **MORT** — test puissant 831 j/8 folds : OOS −8,18 %, t-stat −0,45. Le +11,7 % des 200 j = bruit |
| Exécution maker (sauver le harvest) | RÉFUTÉE — rejet sur t-stat à tous les niveaux de frais |
| CVD divergence / breakout | REJET franc — aucun pouvoir prédictif (in-sample lui-même négatif) |
| Cross-sectional momentum/reversal | REJET — 4 h borderline (+43 %) mais t-stat 1,24, signe instable |

**Leçon transverse :** signal d'entrée + barrière TP/SL sur marché ~efficient = perd contre les frais.
Le gate a tenu la ligne (a empêché de se faire avoir par +11,7 % et +43 %).

### 4.3 Pistes de plus haut niveau (changement de paradigme)

- **L'exécution, pas le signal.** Le funding harvest break-even montrait que l'edge est mangé *exactement*
  par les frais taker (0,045 %/côté). Le levier maker/passif (déjà amorcé : `bandit_policy.py` en shadow)
  pourrait basculer des stratégies break-even en positif — à valider rigoureusement, pas sur 200 j.
- **Plus d'historique.** Beaucoup de verdicts « non concluant » viennent de **12 j d'orderflow = ~1 régime**
  et de tests **sous-puissants** (5–8 folds). Étendre l'historique (HF DB qui s'allonge, OHLCV 4 h longue
  durée) renforcerait les verdicts au lieu de multiplier les tests fragiles.
- **#7 appliqué au LIVE, pas en backtest.** Plutôt que chercher un nouveau signal, un méta-filtre spread/vol
  posé sur les stratégies déjà déployées pourrait améliorer le réel sans risque d'overfit.
